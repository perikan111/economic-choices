## 1. ゲームの目的

経済政策・社会制度を題材にした、**選択式ノベル + 軽量シミュレーション**。

プロダクトとしてのゴールは3段階。

| 段階 | 目的 | 成功の判断基準 |
| --- | --- | --- |
| 第1段階（MVP / Web） | 短編を無料公開し、コンセプトが刺さるか検証する | 最後まで遊ばれる / 複数エンディングを見に再プレイされる |
| 第2段階（Web拡張） | シナリオを増やし、演出・音声を追加する | シナリオ追加がデータ作業だけで回る |
| 第3段階（Steam / デスクトップ） | 本格的な政策・経済シミュレーションとして製品化 | game-core を書き直さずに移植できている |

**設計上の含意**: 第1段階の実装が第3段階の足かせにならないこと。
そのために、後述のとおり「ゲームロジック」と「UI」「シナリオ」「プラットフォーム」を最初から分離する。

## 2. プレイヤー体験

### 中心にある体験

> **「正解のない選択を、自分の責任で選ばされる」**

このゲームの快感は、パズルを解くことでも、物語を鑑賞することでもない。
**善意でやったことが別の場所を壊す**という因果を、自分の手で引き起こすことにある。

### 体験の3要素

1. **トレードオフの実感**
   どの選択にも良い面と悪い面がある。「支持率は上がったが供給が消えた」のような二面性を必ず持たせる。
2. **遅れてくる帰結**
   選択の効果が即座に全部見えると、単なる数値最適化ゲームになる。
   一部の副作用は次のシーン・次の判断の後に顕在化させる（例: 価格上限 → 翌朝の空の棚 → 闇市場）。
3. **再プレイの誘因**
   「あの時こうしていたら」が明確に残ること。エンディング後に選択履歴と主要パラメータの推移を提示する。

### 題材の扱い方（設計原則）

経済政策は現実の政治的争点でもある。以下を原則とする。

- **単一の正解を用意しない。** どのエンディングにも代償を書く。
- **主義主張の宣伝にしない。** 特定の立場を「賢い」「愚か」と地の文で断定しない。評価はパラメータと帰結で示す。
- **現実の政党・政治家・団体を模した固有名詞を使わない。** 架空の都市・架空の人物で構成する。
- **モデルの単純さを隠さない。** これは経済モデルの再現ではなく、トレードオフの体験装置である。エンディング後の解説でそう明示する。

## 3. MVP のゲームループ

```
タイトル
  ↓  [はじめから] / [つづきから]
プロローグ（状況説明の会話）
  ↓
┌───────────────────────────────────┐
│ 状況提示（会話 + パラメータHUD）  │
│   ↓                               │
│ 選択肢の提示                      │  ← 条件を満たさない選択肢は非表示 or 選択不可
│   ↓                               │
│ パラメータ変化 + フラグ更新       │  ← 変化量を画面上で可視化
│   ↓                               │
│ 帰結シーン（会話）                │  ← 条件によって分岐
└───────────────────────────────────┘
  ↑ 2〜4 サイクル繰り返す
  ↓
エンディング判定（パラメータ + フラグ）
  ↓
エンディング本文 + リザルト（履歴・推移）
  ↓
[もう一度あそぶ] → タイトルへ
```

- 1 サイクル ≒ 2〜3 分。全体で **10 分前後**。
- オートセーブは「シーン遷移直後」に 1 スロット。手動セーブは MVP では 1〜3 スロット。

## 4. 第一作「パンの値段を下げろ！」

### 4.1 設定

架空の都市国家。小麦の不作から3週間、パンの店頭価格は平時の約2倍。
プレイヤーは就任間もない市長。財政補佐官の助言を受けながら、3回の政策判断を行う。

登場人物（MVP では立ち絵なし、名前と色のみ）:

| ID | 役割 | 機能 |
| --- | --- | --- |
| `narrator` | 地の文 | 状況描写 |
| `aide` | 財政補佐官 | 数値の提示、財政面の警告 |
| `citizen` | 市民 / パン屋 | 現場の声、副作用の顕在化 |

### 4.2 パラメータ

| ID | 表示名 | 初期値 | 役割 |
| --- | --- | --- | --- |
| `popularity` | 支持率 | 50 | 短期的な人気。上げやすく、失いやすい |
| `budget` | 市財政 | 100 | 使えるリソース。マイナスは財政危機エンド直行 |
| `supply` | パン供給量 | 80 | 実体。ここが崩れると何をしても救われない |
| `price` | パン価格 | 320 | 表面上の指標。下げても supply が伴わなければ意味がない |
| `blackMarket` | 闇市場規模 | 5 | 歪みの蓄積。規制の副作用として増える |

**設計意図**: `price` は「見かけの成果」、`supply` は「実体」。
プレイヤーが `price` だけを追うと `supply` と `blackMarket` に跳ね返る、という構造が本作の背骨。

### 4.3 政策（選択肢）

| 選択 | 主効果 | 副作用 |
| --- | --- | --- |
| 価格上限規制 | `price` 大幅減、`popularity` 増 | `supply` 減 → `blackMarket` 増 |
| 補助金 | `supply` 増、`price` 減 | `budget` 大幅減 |
| 輸入・流通規制の緩和 | `supply` 増、`price` 減 | 効果が遅い、既存業者の反発で `popularity` 微減 |
| 配給 | `supply` の配分を平準化、`popularity` 増 | 運用コストで `budget` 減、`blackMarket` 増 |
| 取締り強化 | `blackMarket` 減 | `supply` 減、`popularity` 減（`blackMarket` が存在する時のみ選択可） |
| 限定的な低所得者支援 | `popularity` 微増、副作用が小さい | 効果も小さい、`budget` 減 |

**条件付き選択肢の例**（フォーマット検証も兼ねる）:
- 補助金: `budget >= 40` のとき選択可。不足時は**選択不可表示 + 理由**（存在は見せる）。
- 取締り強化: `blackMarket >= 20` のとき初めて**出現**（存在自体を隠す）。

### 4.4 エンディング（判定は上から順に最初に一致したもの）

| ID | 仮題 | 判定条件 | 評価 |
| --- | --- | --- | --- |
| `fiscal-crisis` | 支払えない約束 | `budget < 0` | bad |
| `shortage-collapse` | 空の棚 | `supply < 50` かつ `blackMarket >= 40` | bad |
| `black-market-city` | 裏通りの相場 | `blackMarket >= 50` | bad |
| `soft-landing` | 静かな朝 | `price <= 250` かつ `supply >= 90` かつ `popularity >= 55` | good |
| `muddle-through` | とりあえずの均衡 | 条件なし（フォールバック） | normal |

各エンディングは「何が起きたか」に加えて、**代償**を1文以上必ず書く。good エンドも例外にしない。

### 4.5 規模の目安

- シーン数: 15〜25
- 判断ポイント: 3
- エンディング: 5
- 総テキスト量: 6,000〜10,000 字

- [ ] エンディング判定と表示
- [ ] リスタート
- [ ] セーブ / ロード（localStorage、オートセーブ + 手動スロット）
- [ ] 台詞中のパラメータ埋め込み（`{{param.price}}`）

**UI**
- [ ] シリーズホーム / シナリオ選択画面
- [ ] ノベル画面（テキスト、話者名、選択肢、パラメータ HUD）
- [ ] パラメータ変化の可視化（増減の差分表示）
- [ ] エンディング / リザルト画面
- [ ] レスポンシブ（スマートフォン縦持ちで完走できること）
- [ ] キーボード / タップ両対応の送り操作

**品質**
- [ ] game-core の単体テスト（条件式・効果適用・遷移・セーブ復元）
- [ ] シナリオ整合性テスト（未定義 ID 参照ゼロ、到達不能シーンの検出）
- [ ] 通しプレイテスト（選択列を与えて各エンディングに到達できること）

### 明示的に「MVP第一段階では作らない」

- 背景画像と全登場人物分の立ち絵（佐藤美咲の表情差分5枚だけ先行実装）
- 音声・BGM・SE（AivisSpeech 連携含む）
- 文字送りアニメーション、オート、スキップ、バックログ UI
  （※ バックログ用の履歴データは **状態として持つだけ持っておく**。UI は後）
- シナリオエディタ
- アカウント / サーバー保存 / ランキング
- SNS 共有画像生成
- 複数の実装済みシナリオ（シリーズホームには予定作品の catalog metadata のみ表示する）
- 多言語対応（構造だけ塞がない）

## 7. Web版から Steam版への発展方針

### 方針

**同一の game-core を、UI とプラットフォーム層だけ差し替えて再利用する。**
Web 版は「宣伝と検証」、Steam 版は「製品」。シナリオデータは共通。

### そのために MVP 段階で守ること

1. **game-core に `window` / `document` / `localStorage` / `fetch` を書かない。**
   保存もアセット解決も、game-core は**インターフェースだけ**を定義し、実装は外から注入する。
2. **Next.js のサーバー機能をゲーム本体に使わない。**
   Server Actions / Route Handlers / ISR を使わず、静的エクスポート（`output: 'export'`）可能な範囲に留める。
   → そのまま Tauri のフロントエンドとして同梱できる。
3. **セーブデータを純粋な JSON にする。**
   `Date` / `Map` / `Set` / クラスインスタンスを状態に持たない。デスクトップ版ではファイルに書くだけで済む。
4. **アセットを URL 直書きしない。**
   シナリオには論理パス（`aide/worried.png`）だけを書き、URL への変換はプラットフォーム層が行う。

### 移植時に発生する作業（想定）

| 項目 | 作業 |
| --- | --- |
| game-core | そのまま（変更なしが目標） |
| シナリオデータ | そのまま |
| React UI | ほぼそのまま。ウィンドウサイズ・フルスクリーン対応を追加 |
| セーブ | localStorage 実装 → ファイルシステム実装に差し替え |
| 音声・画像 | URL 解決をアプリ内パスに差し替え |
| Steam 連携 | 実績・クラウドセーブ。**新規実装**（Rust 側） |

## 8. 完成の定義（MVP 第一段階）

以下がすべて満たされた時点で「第一段階完了」とする。

1. ブラウザで開いてタイトルからエンディングまで、10分前後で完走できる。
2. 少なくとも 3 つの異なるエンディングに、異なる選択列で到達できる。
3. ページをリロードしても、オートセーブから同じ地点に復帰できる。
4. 新しいシナリオを追加するのに、**JSON を1つ足す以外のコード変更が要らない**。
5. `game-core` に React / Next.js / ブラウザ API への依存が1つもない。
6. 主要ロジックの自動テストが CI で通る。
