## 1. この文書の目的

ECONOMIC CHOICES は、経済政策や社会制度を「説明する」だけではなく、プレイヤー自身に選ばせ、その選択が別の場所へ与える影響を体験させる短編シリーズとする。

新しいシナリオを考える際は、テーマ名だけを保存するのではなく、最低限以下まで考えた状態でこの文書へ残す。

- プレイヤーは誰か
- 何が起きているのか
- 何を守りたい人たちが対立するのか
- プレイヤーが最初に見える問題は何か
- 選択の副作用はどこへ遅れて現れるか
- 同じ数値でも生活実感が違う状態を作れるか
- 最後にプレイヤーへ何を問い返すか

この文書は**公開ロードマップではない**。候補は削除・統合・大幅変更してよい。

## 3. シナリオ制作の原則

### 3.1 正解当てゲームにしない

各政策には、合理的に選ぶ理由と、選んだ後に支払う代償の両方を置く。

「作者が支持する政策だけ、短期・長期・財政・生活のすべてで勝つ」状態を避ける。

ただし、現実の因果関係を無理に50:50へ調整する必要もない。弱い政策を人工的に強化するのではなく、**その政策を選ぶ人が何を守ろうとしているのか**を描く。

### 3.2 登場人物を論点の代弁装置だけにしない

全員に、守りたい具体的なものを持たせる。

例:

- 今日の夕食を確保したい住民
- 来月も店を開けたい事業者
- 税金を使い切れない財政担当
- 不正利用を止めたい行政担当
- 利益機会を探す新規参入者
- 既存制度のもとで投資してきた事業者

反対意見を言わせるためだけの「愚かな人物」を作らない。

### 3.3 一次効果より二次効果を物語にする

選択直後に起こることだけで終わらせない。

基本構造:

1. 問題が見える
2. 政策を選ぶ
3. 目の前の問題が少し動く
4. 人々が新しいルールへ適応する
5. 別の場所に副作用・新しい機会が生まれる
6. その状態を見てもう一度選ぶ

重要なのは 4 と 5。

### 3.4 「制度」ではなく「人の行動」を描く

価格上限、補助金、規制、税などを説明する前に、制度変更を受けて人がどう動くかを描く。

- 売るのをやめる
- 別の街へ運ぶ
- 待つ
- 並ぶ
- 迂回する
- 登録する
- 無登録で続ける
- 品質を落とす
- 新規参入する
- 投資を延期する
- 別の商品へ切り替える

制度の帰結を「行政が決めたから起きた」ではなく、**多数の人の適応の集合**として見せる。

### 3.5 公式指標と生活実感を分ける

第一作の「公定価格」と「実際に食料を入手できるか」のように、見た目の成功指標と生活実感が一致しない構造を優先する。

候補例:

- 家賃 / 実際に借りられる部屋
- 賃金 / 実際に雇われる人数
- 運賃 / 実際に来る車の台数
- 医療費 / 実際の待ち時間
- 電気料金 / 停電・供給余力
- 国産品比率 / 実際の販売価格・品揃え

### 3.6 履歴を尊重する

同じ最終stateでも、それまでに何をしたかで台詞の意味は変わる。

新作では最初から以下を区別する。

- 現在有効な制度
- 過去に実施した制度
- 今回の判断で始めた / 終えた制度
- 一度撤回して戻した制度

「初めて」「続ける」「戻す」「再開する」などの言葉は履歴と一致させる。

## 5. 内部候補ストーリー

以下は**未公開・未決定**。タイトルを含めすべて変更可。

---

### A. 家賃は上げるな！

**テーマ:** 家賃規制 / 住宅供給 / 非価格配分 / 新規建設

**プレイヤー:** 住宅不足が深刻な都市の市長

**発端:** 人口流入で家賃が急上昇。長年住む住民から「家賃を止めてほしい」という要望が殺到する。

**最初に見える問題:** 家賃が高い。

**遅れて見える問題:** 空室の減少、入居審査の厳格化、修繕の延期、新規建設の採算悪化、既存入居者と新規入居者の格差。

**人物候補:**

- 長年住む高齢入居者
- 子どもと引っ越してきた新規住民
- 小規模大家
- 新築を計画するデベロッパー
- 住宅担当職員

**中心の問い:**

> 家賃を安くすることと、住める家を増やすことは同じだろうか？

**候補Decision:** 家賃上限 / 家賃補助 / 建築規制緩和 / 公営住宅 / 現状維持 / 上限対象の限定

**有力度:** 高

---

### B. 外国のチーズに税をかけろ！

**テーマ:** 関税 / 保護貿易 / 消費者負担 / 国内生産 / 報復

**プレイヤー:** 酪農が主要産業の地域政府トップ

**発端:** 安い輸入乳製品が急増し、地元酪農家が廃業危機に陥る。

**最初に見える問題:** 地元生産者が価格競争に負けている。

**遅れて見える問題:** 食品価格、加工業者の原料費、輸出先からの報復、保護された事業者の投資判断。

**人物候補:**

- 地元酪農家
- スーパー店主
- 食品加工会社
- 子育て世帯
- 輸出企業

**中心の問い:**

> 守った産業の費用は、誰が払っているのだろうか？

**候補Decision:** 関税 / 生産補助 / 所得支援 / 無介入 / 段階的関税 / 生産転換支援

**有力度:** 高

---

### C. この工場を潰すな！

**テーマ:** 企業救済 / 補助金 / 雇用 / ゾンビ企業 / 地域経済

**プレイヤー:** 工場城下町の市長または知事

**発端:** 市内最大の工場が赤字となり、閉鎖と大量解雇を発表。

**最初に見える問題:** 数千人の雇用が一度に失われる。

**遅れて見える問題:** 救済の恒久化、競合企業への不公平、税負担、転職の遅れ、新産業の参入余地。

**人物候補:**

- 工場労働者
- 工場経営者
- 地元商店主
- 新規企業の創業者
- 財政担当

**中心の問い:**

> 仕事を守ることと、その会社を守ることは同じだろうか？

**候補Decision:** 救済融資 / 直接補助 / 労働者への直接支援 / 再訓練 / 無救済 / 条件付き整理

**有力度:** 高

---

### D. 最低賃金を2000円に

**テーマ:** 最低賃金 / 雇用 / 労働時間 / 自動化 / 企業間差

**プレイヤー:** 独自最低賃金を設定できる架空都市の市長

**発端:** 生活費上昇に対し、現行賃金では暮らせないという声が広がる。

**最初に見える問題:** 働いても生活が苦しい。

**遅れて見える問題:** 採用数、労働時間、価格転嫁、自動化、技能の低い求職者の入口。

**人物候補:**

- 低賃金労働者
- 求職中の若者
- 飲食店主
- 大手チェーン管理者
- 福祉担当

**中心の問い:**

> 時給を上げることと、労働者の所得を増やすことは同じだろうか？

**注意:** 実証研究の幅が広く、数値効果を単純化しすぎると作品の信頼性を落とす。制作時は研究整理が必須。

**有力度:** 中

---

### E. 家を建てる場所がない

**テーマ:** ゾーニング / 建築規制 / 景観 / 住宅供給 / NIMBY

**プレイヤー:** 急成長する郊外都市の市長

**発端:** 住宅価格が急騰する一方、住民は高層化や用途変更に反対している。

**最初に見える問題:** 家が高い。

**遅れて見える問題:** 建築許可、密度、交通、学校、既存住民の資産価値、若年層の流出。

**人物候補:**

- 持ち家の既存住民
- 家を買えない若者
- 建設会社
- 商店街
- 都市計画担当

**中心の問い:**

> 街並みを守る権利と、新しく住む機会を誰に与えるかは両立するだろうか？

**有力度:** 高

---

### F. 電気代を半分にしろ！

**テーマ:** 公共料金規制 / 発電投資 / ピーク需要 / 供給余力

**プレイヤー:** 独立電力網を持つ架空地域の行政トップ

**発端:** 猛暑と燃料高で電気料金が急騰。住民から料金上限を求める声が出る。

**最初に見える問題:** 電気代が払えない。

**遅れて見える問題:** 発電余力、設備投資、ピーク需要、停電、低所得者支援との違い。

**人物候補:**

- 高齢世帯
- 工場経営者
- 電力会社の運用担当
- 新規発電事業者
- 福祉担当

**中心の問い:**

> 電気料金を低くすることと、必要なときに電気があることは同じだろうか？

**注意:** 第一作の価格上限と構造が近いため、制作順は後ろ。電力特有の「瞬時需給」「予備力」を十分に使える場合のみ採用。

**有力度:** 中

---

### G. 病院は無料になった。でも予約が取れない

**テーマ:** 医療価格 / 待ち時間 / 供給制約 / トリアージ / 財政

**プレイヤー:** 独自の地域医療制度を持つ架空地域の行政トップ

**発端:** 医療費負担への不満から、診療費の大幅軽減を求める運動が起きる。

**最初に見える問題:** 診察代が高い。

**遅れて見える問題:** 需要増、待ち時間、人員配置、緊急度による配分、財政負担。

**人物候補:**

- 慢性疾患の患者
- 救急医
- 開業医
- 子育て世帯
- 医療財政担当

**中心の問い:**

> 無料であることと、医療を受けられることは同じだろうか？

**注意:** 医療は現実制度・健康安全性との距離が近い。架空制度を明確にし、政策教育と個人の医療助言を混同させない。

**有力度:** 中

---

### H. バスを廃線にするな！

**テーマ:** 公共交通 / 補助金 / クロスサブシディ / 利用者負担 / 地域維持

**プレイヤー:** 人口減少地域の首長

**発端:** 赤字バス路線の廃止が発表され、高齢者や学生から存続を求める声が上がる。

**最初に見える問題:** バスがなくなる。

**遅れて見える問題:** 税負担、便数、利用率、代替交通、中心部への資源集中。

**人物候補:**

- 車を運転できない高齢者
- 高校生
- バス会社
- タクシー・乗合事業者
- 財政担当

**中心の問い:**

> 公共サービスを残すことと、今の形の事業者を残すことは同じだろうか？

**候補Decision:** 一律補助 / 利用者限定補助 / デマンド交通 / 新規参入 / 路線縮小 / 存続

**有力度:** 高

---

### I. 銀行を救え！

**テーマ:** 銀行救済 / モラルハザード / 信用収縮 / 預金者保護

**プレイヤー:** 小国の財務責任者

**発端:** 大手銀行の資産悪化が発覚し、取り付け騒ぎが始まる。

**最初に見える問題:** 銀行が破綻しそう。

**遅れて見える問題:** 預金者保護、納税者負担、経営者責任、信用供給、将来のリスク選好。

**人物候補:**

- 小規模事業者
- 預金者
- 銀行経営者
- 競合銀行
- 財務官僚

**中心の問い:**

> 預金者を守ることと、銀行経営者を救うことは同じだろうか？

**注意:** 金融システムの説明負荷が高い。シリーズに慣れたプレイヤー向け。

**有力度:** 低〜中

---

### J. 安い薬が消えた日

**テーマ:** 医薬品価格 / 供給能力 / 在庫 / 調達 / 緊急備蓄

**プレイヤー:** 医薬品調達を担う架空地域の行政トップ

**発端:** 重要な一般薬の不足が発生。値上げへの反発と買い占め批判が起きる。

**最初に見える問題:** 薬が高く、棚から消えている。

**遅れて見える問題:** 在庫形成、生産ラインの余力、輸入調達、備蓄コスト、平時の余剰能力。

**人物候補:**

- 薬局店主
- 製薬会社の生産担当
- 患者家族
- 輸入業者
- 備蓄担当

**中心の問い:**

> 平時の「無駄」をなくすことと、非常時への備えをなくすことは同じだろうか？

**有力度:** 高

## 6. 候補の優先順位を決める基準

各候補を 0〜2 点で評価する。

| 評価軸 | 0 | 1 | 2 |
| --- | --- | --- | --- |
| 一行で状況が分かる | 説明が長い | 少し説明が必要 | タイトルだけでも分かる |
| 選択が本当に迷える | 正解が明白 | 一部迷う | 価値観で割れる |
| 二次効果を描ける | 乏しい | 1つある | 複数の適応がある |
| 人物で対立を描ける | 抽象論中心 | 2立場 | 3立場以上が合理的 |
| 10分程度に収まる | 難しい | 圧縮可能 | 自然に収まる |
| 第一作と違う体験 | ほぼ同じ | 一部違う | 新しい制度メカニズム |
| Economics解説価値 | 低い | 普通 | 誤解されやすく価値が高い |
| 再プレイ性 | 低い | 普通 | 経路で見える情報が大きく変わる |

**12点以上:** 本格設計候補  
**9〜11点:** ストック  
**8点以下:** 保留 / 統合候補

点数だけで自動決定しない。最終的には「いまシリーズに足りない体験」を優先する。

## 7. 公開予定へ昇格する条件

シリーズホームの「実装予定」へ出す前に、最低限以下を満たす。

- 一行の問いが確定している
- プレイヤー役が確定している
- 主要人物が最低4人いる
- Decision 1〜3 の骨格がある
- 各主要choiceに合理的な選択理由と代償がある
- 主要パラメータ候補が決まっている
- Endingを最低5種類イメージできる
- 第一作や既存予定作との役割重複が小さい
- 10分前後で完結できる見込みがある
- 「作者の答えを当てるゲーム」になっていないかレビュー済み

昇格時に、この文書から削除する必要はない。「status: public-planned」と記録して制作履歴を残してもよい。

## 8. 制作開始時の推奨フロー

1. このバックログから1候補を選ぶ
2. 一行の問いを確定
3. 利害関係者を4〜6人作る
4. 政策ではなく「最初の生活上の問題」を書く
5. Decision 1を4択程度で作る
6. 各choiceについて、人々がどう適応するかを書く
7. Decision 2・中盤イベントを作る
8. 履歴を踏まえたDecision 3を作る
9. Ending条件より先にEndingの物語を書く
10. その物語を再現するparam / flagを定義
11. 全経路を機械列挙
12. AIでstate/history意味監査
13. 人間プレイテスト
14. テキスト凍結後にイラスト・音声を追加
